# Троодон: Налаштування TLS (HTTPS)

Цей документ пояснює, як налаштувати SSL/TLS сертифікати для Troodon Load Balancer, щоб увімкнути захищені HTTPS з'єднання з клієнтами (Terminating Proxy).

## 1. Архітектура TLS у Troodon

Troodon використовує потужну бібліотеку **Rustls** (вбудовану в Pingora) для завершення (termination) TLS з'єднань. Усі операції з обробкою криптографії, завантаженням та шарінгом сертифікатів відбуваються *безпечно, асинхронно та без блокувань (Zero-Copy/Arc Sharing)*.

Коли ви вказуєте сертифікати в `config.yaml`, сервер автоматично:
1. Зчитує файли `.crt` та `.key` з диска під час старту.
2. Кешує їх у пам'яті через атомарні вказівники (`Arc`).
3. Для кожного нового HTTPS-з'єднання використовує ці вже завантажені ключі (без I/O на диск).
4. Проксіює розшифрований трафік на backend (upstream).

## 2. Як увімкнути TLS

Щоб увімкнути HTTPS, необхідно оновити `config.yaml`, додавши порт для TLS та секцію з переліком сертифікатів.

### 2.1 Конфігурація `config.yaml`

```yaml
server:
  listen_addr: "0.0.0.0"
  listen_port: 6188     # Стандартний HTTP (незахищений)
  tls_port: 6443        # [КРИТИЧНО] Порт для HTTPS трафіку

# Блок конфігурації TLS
tls:
  certificates:
    # 'main_app' - це внутрішній ідентифікатор сертифіката (ключ масиву)
    main_app:
      cert: "/etc/ssl/certs/troodon.crt"   # Шлях до публічного сертифіката (або ланцюжка)
      key: "/etc/ssl/private/troodon.key"  # Шлях до приватного ключа
```

### 2.2 Формати файлів

Troodon очікує стандартні формати PEM:
* **`cert` (сертифікат):** Файл з розширенням `.crt` або `.pem`, який містить блок `-----BEGIN CERTIFICATE----- ...`. Зазвичай це Full Chain (ланцюжок), який включає сертифікат вашого домену та проміжний сертифікат центру сертифікації.
* **`key` (приватний ключ):** Файл з розширенням `.key` або `.pem`, який містить блок `-----BEGIN PRIVATE KEY----- ...` або `-----BEGIN RSA PRIVATE KEY----- ...`. Паролей на приватних ключах зараз не підтримується.

## 3. Як перевірити, чи працює TLS?

1. Переконайтеся, що файли `troodon.crt` і `troodon.key` існують за вказаними шляхами і процес Troodon має права на їх читання.
2. Запустіть Troodon. У логах ви маєте побачити рядок:
   `🔒 Troodon is binding to TLS (HTTPS): 0.0.0.0:6443`
3. Зробіть тестовий запит за допомогою `curl`:

```bash
# Опція -k/--insecure потрібна, якщо ви використовуєте самопідписаний сертифікат для тестування
curl -v -k https://127.0.0.1:6443/api
```

Ви повинні побачити успішне TLS Handshake:
```text
* ALPN: curl offers h2, http/1.1
* TLSv1.3 (OUT), TLS handshake, Client hello (1):
* TLSv1.3 (IN), TLS handshake, Server hello (2):
...
> GET /api HTTP/1.1
> Host: 127.0.0.1:6443
```

## 4. Використання TLS для Upstreams (Бекендів)

Конфігурація вище налаштовує TLS для **Downstream** (клієнт -> Troodon).
Якщо ви хочете, щоб Troodon спілкувався з вашими бекендами через HTTPS (Troodon -> Backend), це також підтримується автоматично на основі порту бекенду.

Наприклад, якщо у вас `config.yaml`:
```yaml
      - path: "/external"
        upstreams: ["api.external-service.com:443"] # Зверніть увагу на порт 443
```
Troodon автоматично ініціює безпечне TLS з'єднання з цим бекендом. Він також правильно передасть `SNI` (Server Name Indication) на основі наявних налаштувань.
